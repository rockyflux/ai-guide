## 什么是 API 中转站

「中转站」在 AI API 圈子里已经存在很久了。很多人听过这个词，但因为技术门槛、部署成本或其他原因，并没有真正自己部署过，所以对运行方式、成本结构和渠道风险并不清楚。

这页从 **程序结构 → 网络部署 → 成本与倍率 → 渠道来源 → 风险判断** 讲起，帮你读懂中转站报价背后的逻辑。选购具体服务可参考 [AI Coding Plan 订阅选型]({{< relref "ai-programming/coding-plan" >}}) 中的第三方渠道表。

{{% hint info %}}
看中转价格时，不能只看「官方 API 标价额度」，还要看三件事：**订阅真实成本**、**按 API 标价折算出来的额度**、**卖给用户时的倍率**。三层分清楚，才能理解为什么有些站倍率能做到 0.1、0.2，也能看懂为什么过低价格往往意味着更高渠道风险。
{{% /hint %}}

## 常见程序与典型结构

目前中转站一般使用几类程序。市面上大部分中转都是类似结构；即使有自建程序，也多是在这些项目基础上拓展 UI 或功能。

| 程序 | 定位 | 说明 |
|---|---|---|
| **[New API](https://github.com/QuantumNous/new-api)** | API 分发 | 从 [One API](https://github.com/songquanpeng/one-api) 延伸；将 API Key 或上游渠道按规则分发给用户，可设额度、倍率、可用模型等 |
| **[Sub2API](https://github.com/Wei-Shaw/sub2api)** | 订阅分发 | 侧重把 Claude / OpenAI / Gemini 等 **订阅** 分享出来；含防封号、会话粘性、拼车共享等 |
| **[CPA（CLI Proxy API）]({{< relref "setup/cpa" >}})** | 自用 / 拼车 | 从 CLI（Codex、Claude Code 等）拿订阅能力再分发；分发属性较低，一般无计费模块，多用于拼车 |

**典型结构：**

```text
用户 → New API（计费 / 分发层）→ CPA / Sub2API（上游订阅）
或
用户 → Sub2API（直接分发订阅）
```

**New API** 的典型场景：你有渠道可以用美元向 OpenAI 购买 API，再通过中转分发给用户；用户使用时会受后台规则约束（额度、倍率、模型白名单等）。核心是 **分发**。

**Sub2API** 可以把订阅理解成 AI 厂家开的自助餐；订阅分发就像你在店里下了团购，站在店门口把饭端出去分给外面的人。核心是 **分发订阅**，并处理防封号等相关操作。New API 也有类似能力，但不是其重点。

**CPA** 与 Sub2API 一样从订阅拿号，但更侧重从 **CLI 终端程序** 获得订阅能力。分发属性较低，更像自用的订阅中转，一般不带计费，常见于拼车。

## 网络与服务器

### 小型站点（年费通常低于 1000 元）

小型中转站一般使用 VPS。可通过 ping 大致判断所用网络与机房位置。

常见方案：

| 方案 | 说明 |
|---|---|
| **Cloudflare（CF）** | CDN 加速；有技术能力的站点会套优选 IP，给亚太地区加速。[cloudflare.com](https://www.cloudflare.com) |
| **亚太 CDN** | 不少小厂做日本、香港节点，对国内分发较快 |
| **备案国内 CDN** | 如腾讯 EdgeOne、阿里动态加速；需国内备案，风险更高，多数服务商不会采用 |
| **VPS 厂商** | 如 RackNerd（美西机房历史上较稳定）；还有很多小厂与不同线路 |

### 大型站点（年费通常 ≥ 4000 元）

用量大的站点一般会开 OVH 独服或其他独立服务器，追求高带宽（G 口甚至 10G 口）。低于这个价位，配置通常比较一般。

## 中转的真实成本

以下主要以 **GPT / Codex 订阅中转** 为例说明（Claude 渠道逻辑类似，具体数字因平台而异）。订阅真实价格与额度可参考社区工具 [Codex 雷达](https://codexradar.com/)。

### 第一层：平台币与美元换算（倍率陷阱）

很多中转后台会把官网 API 定价直接复制进来，再设置 **1 美元 = 多少平台币**：

- 常见：`1 美元 = 1 人民币`（方便心算）
- 也有：`充 7 元 = 1 美元`、`充 7.3 元 = 1 美元`、`充 6.8 元 = 1 美元` 等

除非站点是真实用美元直接购买官方 API，订阅站本身并不一定需要这样换算——这往往已经是第一层 **约 1/7 的折扣口径**。

### 第二层：倍率分组

**倍率分组** 用来计算用户实际扣费。例如输入 `5`，倍率 `0.1`，实际扣费为 `5 × 0.1 = 0.5` 元。

在 `1 人民币 = 1 美元额度` 的前提下，倍率是在第一层口径上再做折扣。

### 第三层：订阅号怎么换算成「额度」

这里很多人容易混淆：**200 美元不是买了 1600 美元的官方 API 余额**。

更准确的理解是：

1. **Pro 订阅真实成本**约 200 美元/月，折合人民币约 **1400 元**。
2. Pro 订阅按 **订阅制** 给一定使用量，不是按 API 余额计费。
3. 中转站把这个使用量跑满后，按 **OpenAI 官方 API 价格反推**：如果这些请求走官方 API，大概要花多少钱。
4. 后台通常又把 `1 美元额度 = 1 元人民币额度` 记账。

以 Codex 雷达等社区观测为例：每个 **20x Pro** 号一周满额度约 **1600+** 美元口径（此前 Pro 约 2500+，OpenAI 后来降低了额度）。一周折算后约 **1600 元** 平台额度；一个月按 4 周：

```text
1600 × 4 = 6400 元口径额度
```

过程中一般还有 1–2 次重置，总额度约：

```text
1600 × 6 ≈ 9600（约 10000 刀口径）
```

整体一个号大概能跑出 **6000–10000 美元口径** 的额度，而撬动成本约 **200 美元（≈1400 元）**。

若倍率为 **0.2**，用户侧收入约：

```text
6400 × 0.2 = 1280 元
```

只跑出 6400 元口径时，接近亏本；需要重置跑出更多额度，或账号成本更低才有利润空间。因此当前 Pro 号倍率多在 **0.2** 左右，其他渠道多在 **0.1–0.2** 之间。

若倍率 **0.1**、只卖出 6000 元口径：`6000 × 0.1 = 600`，相对 1400 元成本会亏钱（`1400/6000 ≈ 0.23`，`1400/10000 ≈ 0.14`）。

## 除 Pro 号外的常见渠道

这些渠道可以解释为什么有些站曾经能做到极低倍率（甚至 0.01），也解释低价背后的风险。

### Bug Team

指 OpenAI 企业订阅里 **偶发性 bug**。例如曾出现约 **0.52 美元** 开企业账户、分发获取接近 Plus 额度的时段，那段时间出现过不少公益站。这类渠道一般不会长期存在，取决于平台何时发现并修复。

### 首月 Plus

OpenAI 会给不同地区用户 **首月优惠**，只需提供支付方式即可开通。常见获取方式包括欧洲支付（目前仍较常见）、PayPal（半死）、虚拟卡台、GoPay、巴西 Pix 等（多数已不可用）。只要官方还有优惠，就会有人想办法获取；也可能夹杂 K12 等未公开渠道。

### 黑冲

原本指海外盗用信用卡、盗用礼品卡等黑产直销；现在多数指通过 Google 等第三方支付付费后，向平台申诉「被盗」要求追回。平台追回后，OpenAI 侧可能还要 **1–3 天** 才同步知晓——此时会员可能仍在，中转站或许已刷完一周限额的 2500 刀；若有重置，可能刷到 5000 刀。

### 逆向

通过第三方支持流式输出的平台，或不直接支持的产品（如 Kiro、第三方 IDE 等），获取与 OpenAI 不同的接口，自行写注册与转发逻辑分发给用户。对话尚可，coding 体验往往不佳。现在多见于 image2 的 1K 场景，或部分公益站。

### 黑灰产

比「利用规则漏洞」更恶劣、直接损害他人利益的方式：

1. **盗用 Key**：在 GitHub、社群搜索 key、诱导新手发送 key、截留公益站数据，甚至渗透盗用他人 key。
2. **盗用余额**：oneapi、newapi、sub2api 等程序很多由非商业用户自部署；若使用通用密码、开放注册与赠金/邀请赠金，可能被批量注册偷取。
3. **论坛脚本**：在论坛和社区部署监控脚本，公益站、免费 key、分享 key 一经发布即被抓取利用。

## 便宜渠道的风险

来自上述渠道的低价中转，倍率常见在 **0.04–0.1** 区间，通常伴随以下风险：

| 风险 | 说明 |
|---|---|
| **缓存额外成本** | 多号轮询时，上一轮对话在 A 号，下一轮可能在 B 号承接；A 号被封会导致缓存无法命中，实际成本上升 |
| **被二次利用** | 上游可能不是中转自有号，而是被盗用号；发现被盗后可能开启数据截留，甚至上游本就是蜜罐 |
| **降智** | 逆向渠道常附带 IDE 自带上下文，导致上下文被重复覆盖，表现变差 |
| **掺水 / 替换模型** | 低价用户往往不仔细核验；掺入其他模型（如 Mimo）时有发生。豆包等模型有时比 OAI 渠道还贵，掺豆包反而会亏钱，故相对少见 |

## 如何评估与避坑

1. **分清三层价格**：订阅成本 → API 标价折算额度 → 用户倍率。
2. **用工具交叉验证**： [禾维 AI](https://hvoy.ai/) 可做 API 连通性、真假鉴定与价格对比；[Codex 雷达](https://codexradar.com/) 可对照订阅额度口径。
3. **警惕过低倍率**：长期 0.05 以下往往对应更高渠道风险或不可持续。
4. **重要项目走官方路径**：生产环境、高敏感数据优先官方订阅或企业采购；中转更适合补接入、试用或预算有限场景。

{{% hint warning %}}
部分私有渠道可能违反平台服务条款，存在封号、额度缩水、跑路等风险。本文仅作技术结构与成本口径说明，不构成对任何第三方服务的推荐或担保。
{{% /hint %}}
