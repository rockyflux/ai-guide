## 省钱与 Token 治理：预算内把活干完

> **买油**看 [Coding Plan 与渠道]({{< relref "ai-programming/coding-plan" >}})；**少踩油门、按预算跑完全程**看本文。工具清单见 [编程工具对比]({{< relref "ai-programming/vb-code-tool" >}})。

### 真正难的不是「会用 AI」，是预算内做完

个人每个月能砸在 AI 编程上的钱通常就那么几档：一百、两百、一千。额度看着不大，但 Agent 一开，账单涨得很快。

按 DeepSeek 这类低价模型粗算，中度、不克制地用，一个月烧到上千并不罕见；换前沿强模型（GPT 系列顶档、Claude Opus 档一类），同样工作量往往再翻几倍。模型越强，单价越高；Agent 轮次越多，上下文越长，单价再乘次数。

所以问题不是「要不要用 AI」，而是：

> **在固定月预算里，怎么把该做的任务做完，而不是半个月额度见底、活还堆着。**

买更便宜的套餐只解决「油价」；用法不科学，便宜油照样漏光。本文管的是用法：同样把事做成，压低单位任务成本，让预算撑过整月。

![月预算有限 vs 不克制账单飙升](/images/ai-coding-save-money/01-comparison-budget-vs-burn.png)

---

### 先记住一句话

大模型的 Token，已经像水电油一样：

- 每次请求都在**消耗**
- 消耗完了就要**充值**
- 目标不是「不用 AI」，而是：**预算内把活干完，单位任务尽量少烧 Token**

好比开车去同一个目的地：路可以选、车可以选、油门可以轻踩，但终点不变。省钱的本质是**降低完成单位任务的油耗**，不是把车停在半路。

---

### 月预算怎么用：先定油箱，再定车况

把「这个月能花多少」当成硬约束，再选模型和节奏。下面是经验向的用法档位（不是套餐报价表；具体买法仍看 [coding-plan]({{< relref "ai-programming/coding-plan" >}})）：

| 月预算（量级） | 更稳的用法 | 容易炸预算的用法 |
|----------------|------------|------------------|
| **约 ¥100** | 免费网页想清楚 → 低价 / 套餐内模型小步改；强模型只救急 | 全程开 Agent 瞎逛仓库；每题都上顶档模型 |
| **约 ¥200** | 日常用性价比模型；强模型留给架构抉择和反复失败的坑 | 长会话拖几天不交接；Rules / MCP 全家桶常驻 |
| **约 ¥1000** | 可以更敢用强模型，但仍要「规划 / 执行分离」和一事一程 | 以为预算宽就无限重试；一次会话塞多个无关大改 |

同一档预算里，**做成多少事**取决于油耗，不取决于你充了多少。一百块用得克制，可能比两百块乱烧多交付几个功能。

一个实用习惯：月初先估「本月大概要推进几件中等任务」，再倒推每件大概能花多少。超了就降档模型、缩短会话、拆小步，而不是默默加钱。

---

### Token 账单到底在烧什么

一次 Agent 编码会话里，钱很少只花在「你打的那几句字」上。常见消耗包括：

| 油耗项 | 是什么 | 为什么贵 |
|--------|--------|----------|
| **输入** | 系统提示、Rules、聊天历史、读进来的代码、工具返回、截图 | 多轮后上下文越积越长，每轮都可能再带一遍 |
| **输出** | 解释、代码、计划、推理过程 | 模型越爱「想很久 / 写很长」，输出越贵 |
| **工具往返** | 搜索、读文件、跑命令、改文件、再读一遍 | Agent 每多一轮试错，就多烧一轮完整上下文 |
| **缓存未命中** | 前缀变来变去、频繁开新会话又塞不同材料 | 本可便宜复用的前缀，变成全价输入 |

所以：**短回复 ≠ 便宜**。Agent 在后台读了半个仓库、绕了三圈失败路径，账单照样难看。

![Token 账单四类消耗](/images/ai-coding-save-money/02-infographic-token-bill.png)

衡量标准不要盯「单次 Token 单价」，要盯：

> **做成这件事，一共花了多少 Token / 多少钱？**

一次便宜但失败的跑法，往往比一次稍贵但一次做对更浪费。预算紧的时候，这一点更致命：错一次，后面几天都得勒紧。

---

### 省油原则（同样目的地）

1. **先定终点，再踩油门**  
   不知道「做成什么样算完」，模型只能猜；猜错就要掉头重跑，油耗翻倍。

2. **用够用的车，别全程开超跑**  
   改文案、改样式、按计划搬砖，用中小模型；架构抉择、疑难 bug、反复失败时，再上强模型。

3. **少绕路，比少加油更重要**  
   多写清约束、入口文件、验收方式，往往比「省那几十字 Prompt」更能省整段纠错。

4. **只带这一程需要的货**  
   整库粘贴、无关长聊天、臃肿 Rules，都是后备箱里的废铁。

5. **一事一程，卡住就停车**  
   无关任务混在一个长会话里，等于拖着拖车去买菜；死循环时继续催，等于空转烧油。

![省油五原则](/images/ai-coding-save-money/03-framework-five-principles.png)

### 实操：怎么把油耗压下去

#### 1. 规划与执行分开（贵油想路线，便宜油开车）

适合中等以上改动：

1. 用**更强 / 免费网页模型**把需求、步骤、涉及文件、验收标准写进 `plan.md`（或故事文件）。
2. 你自己审一遍：缺约束、缺边界的地方当场补上。
3. 换**更便宜的主力模型**按计划改代码、跑检查。
4. 某一步卡住，再把**那一步**交回强模型，而不是整段会话升级。

小改动（改文案、改一个按钮）不必强行「先规划」：多一次交接，可能比直接改还贵。

免费网页适合「想清楚」：Gemini / AI Studio、Kimi、Qwen、z.ai、DeepSeek 等日常规划够用。真正动仓库、调工具，再交给 Cursor / Claude Code / Codex 一类 Agent。

预算越紧，越要把「想清楚」挪到免费或极低成本侧；付费 Agent 只做改文件和验证。

![规划与执行分离流程](/images/ai-coding-save-money/04-flowchart-plan-execute.png)

#### 2. 一次把任务说成「可交付」

模糊指令逼模型猜；猜错 = 多烧一轮。

差：

```text
帮我做一个博客网站
```

好（同一目的地，路线写清）：

```text
在现有 Next.js + TypeScript 项目里做博客 MVP。
只改/新增：首页、分类页、关于页；全局 TopNav（左 logo，右「首页/分类/关于」+ 主题切换）。
首页：Hero（头像、简介、Banner）+ 纵向 BlogCard 列表（图文 Z 字交错）。
后端：PostgreSQL + CRUD；先只输出建表文档（blog / tag 字段见下），不要直接建库。
参考现有 pages/history 的布局风格；跑现有 lint/test；最后列出改动与未完成项。
```

好 Prompt 通常包含四件事：**结果长什么样、从哪改、别动什么、怎么算做完**。

#### 3. 上下文只点名，不倾倒

Agent 会搜、会读；你的工作是给**起点**，不是把整个项目塞进后备箱。

- 点名文件、函数、路由，或 `@` 相关文件；不要默认「全项目」。
- 报错时贴**完整报错 + 复现命令**；长日志丢进文件让它按需读。
- 视觉问题用截图，逻辑问题用文字；别拿整页截图代替堆栈。
- 文档只给相关章节链接，别塞整本手册。

读盘进模型照样计输入。点名文件省的是「乱翻」；只读相关片段省的是「整文件灌进上下文」。

#### 4. 一事一聊，长会话要交接

- 同一任务、上下文仍有用：继续聊。
- 换无关任务：**新开会话**。
- 要换会话但工作未完：让模型写一段交接（目标、进度、关键文件、已失败尝试、下一步），你审完再贴进新会话；复杂的可落到 `handoff.md`。
- 工具提供「压缩上下文」时，在阶段节点用，并要求保留需求、路径、未解失败；别每隔几轮就压一次（压缩本身也耗油，还可能打穿缓存）。

#### 5. 常驻说明要瘦：Rules / AGENTS.md / CLAUDE.md

这些文件几乎**每轮都可能进上下文**，是固定油耗。

留：

- 怎么装依赖、怎么跑测试
- 项目硬约束（语言、目录、禁止事项）
- Agent 反复犯的错（写成一条短规则）

挪走：

- 偶尔才用的长流程 → Skill / 单独文档，用时再读
- 过时模型弱点补丁（「务必检查两遍」一类）→ 模型升级后审计删掉

一条经验：根目录说明宁可短，也不要「百科全书」。目录级规则只挂在真正需要的路径上。

#### 6. 小步验证 + Git 存档点

拆成能独立验收的小任务：改完 → 跑相关检查 → `commit`。

好处：

- 单次上下文更短，模型更稳
- 跑偏可 `git reset` / 回分支，避免「擦屁股」再烧一轮
- 复杂 issue 用独立分支，验完再合并

Agent 陷入重复失败时：**打断**，说明已失败证据，换思路或新开会话；不要空转催「继续」。

#### 7. MCP / 技能按需开，不按炫开

每个 MCP、每份长 Skill 描述都会占输入。只开当前任务需要的；文档类用 Context7 这类「用时拉取」，比把整库文档塞进 Rules 更省。

### 选车：别全程超跑

| 路况 | 更合适的用法 |
|------|----------------|
| 改文案、简单 UI、按计划改文件 | 中小 / Flash / mini 档 |
| 日常功能开发、常规调试 | 主力性价比模型（国内 Coding Plan 里的编码向模型等） |
| 架构决策、诡异 bug、多次失败 | 前沿强模型 |
| 纯头脑风暴、写 PRD / 计划 | 免费网页或强模型网页，少在 IDE Agent 里空转 |

强模型规划 → 便宜模型执行 → 必要时强模型复盘，是常见的「混合油耗」套路。细节选型与价格口径见 [Coding Plan 与渠道]({{< relref "ai-programming/coding-plan" >}}) 与 [大模型价格]({{< relref "ai-programming/model-price" >}})。

模型会越来越强，也可能越来越贵；**按任务选档、按预算控节奏**不会过时。未来若顶档模型单价更高，这套分流只会更重要，而不是更次要。

---

### 免费额度：公交与太阳能，不是主引擎

免费网页、免费 CLI 额度、学生优惠，适合：

- 规划、对比方案、学 API、写文档草稿
- 验证「这个想法值不值得进付费 Agent」

不适合指望它们扛整天生产级 Agent 编码。额度收得快、限速多、模型档位也不稳定。

可以当「公交」用的入口（以各站官方为准）：Google AI Studio、各家网页 Chat、Gemini CLI 的免费档、GitHub Copilot Free、学生优惠等。买稳定油箱仍看 [coding-plan]({{< relref "ai-programming/coding-plan" >}})。

### 出门前 30 秒检查清单

- [ ] 这个月油箱还剩多少？这程值不值得烧？
- [ ] 终点清楚吗？（做成什么样、怎么验收）
- [ ] 这程用得着最贵模型吗？
- [ ] Prompt 里有没有入口文件 / 别动范围 / 验收命令？
- [ ] 有没有把整库或无关长历史拖上车？
- [ ] Rules 是否又胖了一圈？
- [ ] 是否该新开会话，而不是在旧车上继续绑集装箱？
- [ ] 卡住时是换思路，还是在空转？
