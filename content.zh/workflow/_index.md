## 协作与工作流：把“会用 AI”变成“能稳定协作交付”

当你已经会用模型、也配好了环境，下一步不是继续堆工具，而是把 **任务拆解、角色分工、上下文传递、验证闭环** 这套流程跑顺。  
本栏目聚焦的就是这件事：如何把 Claude、Codex、Gemini 这类模型，以及 Rules、Skills、MCP、Specs 等机制，组织成可复用、可迭代、可交付的工作流。

你可以把这里理解成站内的“编排层”：

- 上游承接 **[AI 编程实战]({{< relref "ai-programming/_index" >}})** 里的模型、环境与方法论
- 下游连接 **[跑项目闭环]({{< relref "project-practice/_index" >}})** 里的案例、配置与实战落地
- 中间解决的核心问题是：**多人/多 Agent 怎么协作，复杂任务怎么收敛，长期项目怎么降低返工**

## 先从哪里开始？（按目标直达）

### 1. 想先建立整体地图：有哪些主流协作范式

- [工作流项目集]({{< relref "workflow/ccg-workflow" >}})  
  这是本栏最适合先看的总入口：把常见工作流项目按定位串起来，便于先建立全景地图。
- [AI 编程实战]({{< relref "ai-programming/_index" >}})  
  如果你还没把模型、环境、CLI 和基础方法论配顺，建议先回这里补齐底座。

### 2. 想直接上强度：把多模型 / 多 Agent 真正编排起来

- [ccg-workflow(CCG)]({{< relref "workflow/ccg" >}})  
  聚焦 Claude + Codex + Gemini 的组合协作，适合对“多模型分工”最感兴趣的读者。
- [oh-my-claudecode(OMC)]({{< relref "workflow/oh-my-claudecode" >}})  
  聚焦 Claude Code 生态下的多智能体协作与流程封装。
- [Trellis]({{< relref "workflow/trellis" >}})  
  聚焦跨客户端、跨工具链的一致规范，适合希望统一接入方式的人。

### 3. 想把流程做稳：减少返工、沉淀长期可复用规范

- [Get Shit Done(GSD)]({{< relref "workflow/gsd" >}})  
  偏规格驱动和上下文工程，强调从任务拆解到执行验证的闭环治理。
- [Superpowers]({{< relref "workflow/superpowers" >}})  
  偏 Skills 驱动的软件开发工作流，适合把 SOP、能力模块和工具调用结构化下来。
- [跑项目闭环]({{< relref "project-practice/_index" >}})  
  如果你更关心“如何在真实项目里跑通”，可以再连到项目实践栏目。

## 适合什么时候回来看这个栏目

- 当你发现“单次对话能写代码，但项目一大就乱”时
- 当你开始关心 Agent 分工、上下文治理、计划与验证分层时
- 当你想把一次次成功经验沉淀成团队可复用流程时
- 当你希望把 AI 从“辅助写代码”升级为“稳定协作的生产系统”时
