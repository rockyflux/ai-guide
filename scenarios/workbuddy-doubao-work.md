# WorkBuddy 与豆包工作

目标：搞清 **网页版聊天 vs 桌面端 Agent** 的差别，用 [WorkBuddy](https://www.codebuddy.cn/work/) / [豆包工作](https://www.doubao.com/work) 把「能对话」推进到「能直接改本机文件、控办公软件」。

产品对比与选型见 [AI 办公桌面端](/products/ai-office-desktop.html)。桌面端擅长本机文件与办公软件；若要读写**消息、日程、待办、多维表格、云文档**等平台原生能力，在 WorkBuddy / 豆包工作里接入官方 CLI 即可（见 [桌面 Agent 接入办公 CLI](/scenarios/ai-office-practice.html)）。

---

## 为什么网页版不够用

手机版、网页版豆包（以及同类对话产品）很适合问答、写稿、出点子，但能力边界很清楚：

- **碰不到本机**：不能直接读写本地文件夹、改 Word / Excel、开浏览器点按钮。
- **交付停在「文字」**：结果多半是一段回复，你还得自己复制、排版、粘进软件。

要把「说清楚一件事」变成「电脑上真的做完」，需要的是**桌面端 Agent**（Desktop Agent）：装在电脑上的办公智能体，能调本机文件、办公软件、浏览器，以及 Skills / MCP / 连接器。

WorkBuddy、豆包工作、DuMate、千问办公等，都属于这一类。体量与定位见 [AI 办公桌面端](/products/ai-office-desktop.html)。

## 订阅：像加油、像充话费

桌面端相对网页版更重能力，也通常要**付费订阅**（或按额度计费）。

当前各大厂常做拉新活动：免费试用数月，或送额度——方便上手，但额度几乎一定会封顶。长期高频用，订阅就像：

| 类比 | 含义 |
| --- | --- |
| 汽车加油 | 没有「油」，车开不远；任务跑不动 |
| 手机话费 / 流量 | 上网本身是日常刚需，不是可有可无的奢侈 |

实务上，个人月支出多在 **几十到数百元** 区间，按用量与所选模型浮动。把订阅当成「生产力油费」，比纠结「要不要买」更有用——真正拉开差距的是：**同样的额度，能不能更快、更稳地交付**。

**订购渠道**：走官方买 token / 订阅通常更稳，但价格偏贵。第三方中转往往更便宜，适合控成本；质量、稳定性与风控参差不齐，选购要谨慎。渠道对照、风险与验真方式见 [Coding Plan 与渠道](/programming/coding-plan.html)。

## WorkBuddy 大概能做什么

就当前市场体量与办公打通深度而言，**WorkBuddy 常处在第一梯队**（月活等数据见选型篇）。它侧重把各大办公软件串起来：自然语言下达任务后，可直接参与文档编写、图片与视频处理等流程，而不只是「给你一段建议」。产品能力与界面总览见官方 [WorkBuddy 简介](https://www.workbuddy.cn/docs/workbuddy/Overview)。

豆包工作则更贴飞书生态（调研、文档、PPT、电脑与浏览器操作、定时任务），适合已经泡在飞书里的团队。两者都是桌面端 Agent，选型看生态与习惯即可，用法心法相通。

WorkBuddy 只是桌面办公里的一个选项：目前免费额度与功能较完善，更容易让更多人上手喜欢。同类与更多工具可参考 [IDE 与编程工具](/programming/vb-code-tool.html)——只要是编程向 Agent / IDE，往往都能做办公自动化，因为底层都是代码调用（读写文件、跑命令、调 CLI / MCP）。

需要给 Agent 单独邮箱时，可用 QQ 邮箱的 [Agent Mail](https://agent.qq.com/)：专为 Agent 设计的邮箱，方便收发、归档与任务触发，而不必把个人主邮箱直接暴露给自动化流程。

## 交付格式：别被 Word「默认选项」绑死

过去很多人习惯用 Word 交结果。Word 能用，但对 **AI 生成与展示** 并不友好：版式复杂、结构松散，模型也不如写 Markdown / HTML 那么顺手。

更稳妥的默认交付：

| 格式 | 适合做什么 |
| --- | --- |
| **Markdown** | 报告、说明、清单、技术方案；结构清晰，Diff 友好 |
| **HTML** | 需要版式、可交互预览、对内分享的页面 |
| Word / PPT | 对方强制要 `.docx` / `.pptx` 时再导出；或交给 Agent 按模板灌内容 |

原则：**先让 AI 用它最擅长的格式把内容做对，再按对方要求转换**，而不是一上来就在复杂排版里硬扭。Claude Code 团队的实践也倾向这种分工：Markdown 适合当轻量底稿，HTML 更适合给人读、给人点（规格、PR 说明、原型、交互报告等）——详见 [HTML is the new Markdown：来自 Claude Code 团队的实践](https://developer.aliyun.com/article/1733857)。

## 核心隐喻：从走路到开车

干一件事，好比去一个目的地：

- **传统方式 ≈ 走路**：慢，极度依赖个人体能与认路能力。
- **桌面端 Agent ≈ 开车**：快得多，但要会开车，还要加油。

会开车 ≠ 自动到站。同样是开车到目的地：

- 路线选错 → 绕远、迟到  
- 油门乱踩 → 油耗高、额度烧光  
- 技术不熟 → 中途抛锚、反复重开任务  

用 Agent 也一样：**目的地相同，技巧不同 → 耗时不同、额度（油耗）差很多**。下面几条，就是「开好这辆车」的最小技巧集；更完整的官方清单见 [WorkBuddy 10 个上手技巧](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Efficient-Tips)：

1. 清晰表达，给 WorkBuddy 下达明确任务
2. 小步快跑，一次搞定一件事
3. 不满意就调整，别一轮定生死
4. 先本地后远程，稳扎稳打不踩坑
5. 给 WorkBuddy 一个身份，它就更专业
6. 给 WorkBuddy 看例子，比说一堆要求更管用
7. 善用多任务，别在烂上下文里死磕
8. 记得频繁备份和做版本管理
9. 用好自动化，让 WorkBuddy 自己持续干活
10. 学会「偷懒」+ 合理激发 WorkBuddy 的输出

## 上手三件事

### 1. 选模型：性价比最优解，不是最便宜

便宜但完成质量差的模型，往往要多轮返工，**总油耗反而更高**。

- 简单整理、改格式、短文 → 可用轻量 / 便宜模型  
- 多步办公、跨软件、要判断取舍 → 上更强的主力模型  
- 不确定时：先用「自动 / 推荐」，跑通一次后再按账单微调  

目标不是「单次最便宜」，而是 **「单位交付成本最低」**。

### 2. 把问题说清楚，并点名工具

Agent 不是读心术。一次任务里尽量写清：

- **目标**：交付什么（文件路径、格式、完成标准）  
- **约束**：不能改什么、截止时间、必须保留的字段  
- **工具**：需要时直接指定 Skills、专家、MCP（例如「用某某 Skill 出封面」「走飞书 CLI 发消息」）

模糊的一句「帮我弄一下那个表」，等于让司机自己猜目的地。

### 3. 接好连接器（含平台 CLI）

连接器、MCP、**办公平台 CLI** 都是把 AI 接到第三方应用的桥：文档、表格、日历、IM、网盘等。接好之后，任务才能从「口头方案」落到「对方系统里真的改了」。

- **产品内连接器 / Skills**：WorkBuddy 侧重腾讯文档 / 企微等；豆包工作侧重飞书。优先用界面里已提供的连接与技能。
- **官方 CLI**：消息、DING、日程、待办、多维表格、通讯录等，桌面端往往触达不全；按 [桌面 Agent 接入办公 CLI](/scenarios/ai-office-practice.html) 装好 CLI 与 Skill 后，在任务里点名调用即可（例如「查今日日程并发群提醒」）。
- **CLI vs MCP**：CLI 更适合写操作与全链路编排；MCP 更适合当知识库 / 上下文源。详解见 [桌面 Agent 接入办公 CLI](/scenarios/ai-office-practice.html)。

## 使用细节（少踩坑）

| 做法 | 原因 |
| --- | --- |
| **选对模型 + 选对技能** | 模型负责推理，技能负责固定流程；两者错配会空转 |
| **一个会话一个主任务** | 中途塞进无关新任务，上下文被污染，返工与幻觉都变多 |
| **控制对话轮次** | 轮次过多说明目标没一次说清；宁可新开任务，也不要无限续聊 |
| **多用定时任务** | 日报、同步、巡检等可设自动或手动触发，减少「每次重新口述」 |

可记成一句：**说清一次 → 选对工具 → 专事专开 → 重复的事交给定时**。

## 建议练习路径

1. 装好 WorkBuddy 或豆包工作，用活动额度跑通一次「读本地文件 → 改内容 → 写回」。  
2. 同一任务分别试轻量模型与主力模型，对比质量与消耗。  
3. 装一个明确的 Skill（或连接器），用「点名调用」完成一次可验收交付。  
4. 按需在 WorkBuddy / 豆包工作里接入企微 / 钉钉 / 飞书 CLI（见 [桌面 Agent 接入办公 CLI](/scenarios/ai-office-practice.html)），跑通「查日程 / 写文档 / 发消息」之一。  
5. 把每周重复动作做成定时任务（自动或一键手动）。  

跑通以上几步，桌面端 Agent 就从「会打开」变成「本机 + 办公平台都能稳定省油到达」。
