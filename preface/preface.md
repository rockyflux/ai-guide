# 前言

## 从「会聊天」到「能交付」

打开对话窗口，抛出问题，往往能得到像样的答案。这件事已经不再稀奇。稀奇的是另一面：同样一批模型、同一套工具，有人能稳定交付项目，有人却卡在「偶尔很强、经常翻车、账单不明、上下文越用越脏」。

差距很少出在「会不会问问题」，而在于有没有把整条链路当成工程来管：选什么模型、怎么接入、用什么 Agent、Rules / Skills / MCP 怎么配、多轮任务如何拆、失败后如何恢复。

本指南要回答的是：**智能已经被造出来了，接下来如何把它组织起来、约束起来，并转化为可以复用的开发生产力。** 人作出判断与取舍，模型与 Agent 承担检索、起草、改码、跑测、整理上下文。同一套选型、同一套工作流、同一套 Agent 资产，换项目也能照着落地。

默认读者已有开发经验。内容按任务组织，直接回答：先做什么、后做什么、卡在哪一环该翻哪一章。


## 为什么要有这本指南

市场上不缺「某工具 10 分钟上手」的短文，也不缺模型能力对比的截图。缺的是把决策串成一条线的中文材料：

- **选型挑战**：模型、IDE、Agent CLI、Coding Plan、中转站、聚合平台——选项太多，口径不统一，容易买贵、配错、用散。
- **工程化挑战**：从单次对话到可复用工作流——Rules、Skills、MCP、Hooks、Subagents 各管什么，如何组合才不互相打架。
- **成本挑战**：Token 账单往往不在「模型单价」，而在上下文脏、工具乱、多轮空转；需要可执行的治理，而不是口号。
- **交付挑战**：工具会用不等于项目能交；需要可照着跑的 SOP，把选型与配置落到真实仓库里。

文字生产成本下降之后，仍然稀缺的是这四样：

- **自洽的概念与路径**：Agent、Workflow、Skills、MCP、Harness 在不同人口中未必是同一件事。需要一套前后一致的叙事，让读者在同一个上下文里选型与决策。
- **判断**：模型擅长把已有信息重组得通顺。哪条路径适合国内开发者、哪类渠道风险更大、什么时候该上多 Agent，需要有实践经验的人做取舍。
- **经验**：真实仓库里反复踩过的坑——上下文污染、工具权限过宽、中转倍率不透明、工作流架子过大——很难被语料里的「最佳实践」列表替代。
- **教训**：内容越丰富，「什么不该做」往往比操作清单更值钱。失败模式写清楚，读者就能少付一遍学费。

工具与模型变化很快，书中的判断与清单会被修正。这份文本以开源方式维护，方便协作更新和社区纠错。

## 这本指南主要讲什么

全书按侧栏阅读顺序展开：编程选型 → Agent 构建 → 项目实践 → 学习资源 → 应用选型。

**编程选型篇**  
先看 [全流程总览](/programming/full-pipeline.html)，再按侧栏往下：评测、编程工具与 Agent 横评、[协作工作流选型](/programming/ccg-workflow.html)，然后是 Coding Plan / 中转 / 聚合、省钱与 Token 治理，最后是开发环境、增强工具与卸载清理。

**Agent 构建篇**  
把「对话」模块化成可长期复用的资产。侧栏顺序是 Prompt、Skills、MCP、Hooks、Subagents。

**项目实践篇**  
用真实 SOP 跑通闭环：Cursor / Codex / Kiro 开工包、WSL、办公与设计原型、Claude Code 最佳实践与开发笔记、绘图练习与 Stitch × Figma × MCP。

**学习资源篇**  
系统学习路线、社区资源、教程速查与 GitHub 周边工具。按需查阅，不必按序通读。

**应用选型篇**  
面向编程之外的场景：办公桌面 Agent、对话工具、智能体平台、绘图与视频、OpenClaw 生态与开发周边，按场景选型。

站内另有 [2026 Agent 开发者调研报告](/survey.html)，可与正文对照阅读。
